Chapter 2 of 4

The Epiphany: Separating the Event from the Journey

Why the click handler should never know about your table's layout.

Story Index

1. The Core Realization

In Chapter 1, we saw how fragile code becomes when event handlers perform DOM scraping directly.

The Epiphany:
An event listener should have exactly one job: detect the user's action and hand off the starting element (event.currentTarget). It should never know how many columns exist, where the row starts, or how cells are read.

If you separate the Trigger from the Extraction Journey, you can change your table layout at any time without ever touching your JavaScript event listener again.

2. The 3-Stage Mental Model

Instead of a mess of parent-child traversals, every data extraction from a table can be broken down into three clean, linear stages:

Stage 1: Anchor
Ascend to Boundary

From the clicked element, climb up to establish the container scope (the row <tr>).

Stage 2: Filter
Drill Down to Payload

Inside that row, query only the cells holding actual data, ignoring buttons and serial numbers.

Stage 3: Bridge
Map to Schema

Convert the gathered DOM cells into domain properties using a configured column schema.

The Data Flow:
[Clicked Button] → [Row Element] → [Array of Cells] → { itemName: "...", category: "..." }

3. Expressing the Journey as a JSON Recipe

Because these three stages are universal, we don't need to write custom JavaScript functions for each table. Instead, we express the extraction steps as a simple JSON pipeline: 

[
  {
    "narration": "Step 1: Anchor to row boundary",
    "sourcePath": { "fileName": "root" },
    "func": "closest",
    "arguments": { "selector": "tr" }
  },
  {
    "narration": "Step 2: Collect payload cells",
    "sourcePath": { "fileName": "previous" },
    "func": "querySelectorAll",
    "arguments": { "selector": "td:not(:last-child)" }
  },
  {
    "narration": "Step 3: Map cells into an object",
    "sourcePath": { "fileName": "previous" },
    "func": "mapValues",
    "arguments": { "read": "text" }
  }
]

Notice how readable this is! Any developer, tester, or even backend service can inspect this JSON and immediately understand the exact journey from button click to JavaScript object.

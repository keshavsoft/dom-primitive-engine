DOM Primitive Engine V9

Example: Extract one table row into a JavaScript object.

The central idea

The application knows when the user clicks a button. The instruction contract describes how to find the relevant DOM elements and read their values. The engine executes those instructions in order. The result is ordinary JavaScript data.

1. The table we want to read

Item Category Price Action
Keyboard Accessories 35
Mouse Accessories 20

Each row represents one item. When the user clicks Extract, we want the data from that row only—not from every row in the table.

2. Follow the click, step by step

STEP 1 — Receive the click

The application attaches a click listener to the table. The clicked button is available through event.target or, when using a delegated listener, event.currentTarget depending on how the listener is wired. The example must use the property that matches its actual event handler.

The application passes the clicked element to the extraction pipeline. The pipeline does not decide which button the user clicked.

STEP 2 — Find the containing row

Starting from the clicked button, use closest("tr") to locate the row that contains it. 

button → closest("tr") → selected row

This is important because the same instructions can work for either the Keyboard row or the Mouse row. The starting element determines which row is selected.

STEP 3 — Read the row's cells

Within the selected row, use querySelectorAll("td") to collect its data cells. 

selected row → querySelectorAll("td") → cell collection

The Action cell is also a td, so the column mapping must deliberately describe the three data columns we want to extract.

STEP 4 — Convert cells into an object

The column configuration supplies the property names. The engine reads each configured cell and pairs its value with the corresponding property name. 

{
  "columns": ["itemName", "category", "price"],
  "read": "text"
}

In this example, columns is an ordered mapping: the first data cell becomes itemName, the second becomes category, and the third becomes price.

3. The pipeline's responsibility

Conceptually, the instructions form an ordered sequence: 

[
  { "op": "closest", "args": { "selector": "tr" } },
  { "op": "queryAll", "args": { "selector": "td" } },
  {
    "op": "toObject",
    "args": {
      "columns": ["itemName", "category", "price"],
      "read": "text"
    }
  }
]

Each operation receives the result of the preceding operation. The engine executes the operations in sequence and returns the last operation's result.

Contract decision to review

This example uses the current short property names, op and args. If we decide to use operation and arguments instead, we must update the engine, examples, tests, and documentation together. The document should describe whichever contract we actually adopt.

4. Expected result

If the user clicks Extract in the Keyboard row, the output should be:

{
  "itemName": "Keyboard",
  "category": "Accessories",
  "price": "35"
}

If the user clicks Extract in the Mouse row, the same instructions should return that row's values instead.

5. Who is responsible for what?

Part Responsibility
Click handler Detects the user's action and supplies the starting element.
Instruction contract Describes the operations and the information each operation needs.
Pipeline Executes instructions in order and passes results forward.
DOM primitives Perform the actual DOM lookup and value-reading work.
Column mapping Defines the property names and their corresponding cell positions.
Output Returns a plain JavaScript object that application code can use.

6. The design principle

The application handles the event. The instructions describe the extraction. The engine executes the instructions. The result is data.

Keeping those responsibilities separate makes the same extraction engine reusable for other tables and, with an appropriate instruction contract, for forms and other DOM structures.
